Agentes e automações com IA

Todos rodam hoje para clientes reais. Abra um para ver como eu montei e quanto custa.

Os padrões de agente que eu uso

Escritor e revisor
Um passo escreve e outro confere contra regras fixas. Se reprovar, volta para reescrever. Está no motor do blog.
Roteamento
O agente lê cada item da caixa de entrada e decide o destino: tarefa, ideia ou espera. Está no resumo da manhã.
Pessoa no laço
A IA propõe e uma pessoa aprova antes de publicar, faturar ou emitir nota. Está no painel de notas fiscais.
Busca por sentido (RAG)
O modelo consulta o que já existe antes de escrever, para não repetir. Está nas páginas de cidade.

14 sistemas

  1. Escreve e confere artigos de SEO local três vezes por semana. Cada um fica pronto para uma pessoa revisar e publicar.

    O texto passa por 14 regras antes de chegar ao WordPress. Se reprovar, o Claude reescreve até três vezes. Cada artigo custa entre US$ 0,10 e US$ 0,21.

    As pautas ficam numa fila no Supabase e o Claude escreve pela API. O validador confere keyword, título, densidade e links antes de qualquer coisa ir para o WordPress. O post entra como rascunho, com três fotos que não se repetem, FAQ com schema e os campos do Rank Math preenchidos. Depois que alguém publica, o OneUp leva o post para o perfil da empresa no Google.

    • Claude API
    • GitHub Actions
    • Supabase
    • WordPress (plugin próprio)
    • OneUp
    • Formspree

  2. Lê a planilha de pedidos toda manhã e monta o pedido de nota fiscal pela API do ERP, com o total fechando no centavo.

    Já criou pela API pedidos de 80 e 103 linhas. Quando o caso foge da regra, a pessoa descreve em texto e o Claude propõe os itens. Quem emite a nota é sempre uma pessoa.

    O n8n faz a ponte com o OMIE e só mexe em pedidos de nota que ainda não foram faturados. O painel, em React na Vercel, mostra a fila por data de saída, o espelho da nota, a troca de CNPJ com o imposto recalculado e o faturamento, que pede o número do pedido digitado para confirmar.

    • OMIE API
    • n8n
    • React
    • Vercel
    • Claude Sonnet
    • Google Sheets

  3. O cliente digita a cidade e o bot responde com o representante daquela região e o link do WhatsApp dele.

    Cobre a lista de representantes do Rio Grande do Sul, de Santa Catarina e do Paraná, e acha a cidade mesmo com erro de digitação, sem acento ou com o estado por extenso.

    O bot da Multi360 chama um webhook na Vercel. O webhook normaliza o texto, compara com a lista de cidades por distância de edição (Levenshtein) e responde no formato de conversa que a Multi360 espera. Um segundo fluxo pede o e-mail, confere o formato, manda o lead para o Make e passa a conversa para uma pessoa.

    • Multi360
    • Next.js
    • Vercel
    • Make
    • Levenshtein

  4. Duas contas do Claude e as rotinas do n8n leem e gravam no mesmo cofre de notas, então nenhuma conversa começa do zero.

    O resumo da manhã roda nos dias úteis às 6h40 e a revisão semanal, às sextas. São 77 arquivos versionados no GitHub.

    O Obsidian sincroniza com um repositório privado, e o acesso passa por um workflow do n8n que exige autor e limita as pastas de cada pessoa. O resumo da manhã é um agente agendado: lê cada linha da caixa de entrada, decide se ela vira tarefa no TickTick, ideia ou espera, e avisa se algum deploy ou workflow falhou.

    • Claude
    • n8n
    • Obsidian
    • GitHub
    • TickTick

  5. Busca nas páginas do site pelo sentido do texto, para que as páginas novas de cidade não repitam as que já estão no ar.

    O índice tem 51 páginas e 526 trechos. O último lote, de 8 páginas novas, saiu sem nenhuma sequência de 10 palavras igual a um trecho do site.

    Os embeddings usam o modelo gte-small dentro do próprio Supabase (pgvector com índice HNSW). Uma Edge Function indexa e busca, e um job no pg_cron mantém os vetores atualizados. Não precisou de fornecedor novo nem de chave de API.

    • Supabase pgvector
    • gte-small
    • Edge Functions
    • pg_cron
    • n8n

  6. O Claude escreve a copy e escolhe o enquadramento, e a arte sai de um template HTML com os tokens da marca. Todo post espera numa fila de aprovação.

    As métricas voltam em 24 h, 72 h e 7 dias. O Claude propõe regras de criativo a partir delas, e uma regra só entra no próximo prompt depois que eu aprovo.

    O satori e o resvg transformam HTML em PNG em segundos, sem navegador. O n8n cuida do relógio e dispara o GitHub Actions, que roda o motor. Seis tabelas no Supabase, todas com RLS, guardam marca, fila, posts, métricas, regras e o registro de cada execução.

    • Claude API
    • satori
    • resvg
    • n8n
    • GitHub Actions
    • Supabase
    • OneUp

  7. Um pedido por webhook vira vídeo pronto na pasta do cliente, em 9:16 e 4:5, com e sem legenda.

    Cada render leva uns 3 minutos e entrega 10 arquivos, com o áudio normalizado a −14 LUFS. O custo extra é quase zero.

    Python, Playwright e ffmpeg rodam no GitHub Actions a partir de um job em JSON. O n8n dispara o render, recebe o aviso quando termina, baixa os arquivos e salva no Google Drive do cliente. A legenda sai gravada no vídeo e também em .srt, para quem quiser finalizar à mão.

    • Python
    • Playwright
    • ffmpeg
    • GitHub Actions
    • n8n
    • Google Drive

  8. Coleta o perfil do cliente, grava fotos e legendas num repositório e deixa o contexto pronto para montar a página.

    Uma coleta de 50 posts leva de 3 a 5 minutos e custa centavos de dólar. Endereço, preço e depoimento só entram na página se o cliente informar.

    A Apify roda pelo n8n, as mídias vão para o GitHub com um media.json tipado, e a página é feita em React, TypeScript e Tailwind, publicada na Vercel. O processo virou duas skills do Claude: uma faz a coleta e a outra monta a página e confere o visual.

    • n8n
    • Apify
    • GitHub API
    • React
    • Tailwind
    • Vercel
    • Claude Skills

  9. A IA só gera imagem quando não existe foto real do produto, e cada imagem gerada é comparada com a embalagem verdadeira.

    Os 260 produtos da loja têm foto. 199 vieram do cardápio antigo e o resto foi gerado e revisado. Oito imagens foram recusadas por cor ou versão errada.

    Gero com Gemini e gpt-image-1-mini (pelos créditos do n8n) e recorto o fundo com IS-Net rodando localmente. Vale uma regra para todas as peças: o produto real aparece como na foto, sem filtro e sem trocar de cor. O mesmo processo faz as peças de produto da BR Oxigênio.

    • Gemini
    • gpt-image-1-mini
    • rembg (IS-Net)
    • n8n

  10. Toda segunda às 10h, varre o sitemap e grava um relatório com os erros de modelo que passaram.

    Procura, por exemplo, o nome da cidade usada como modelo esquecido no texto, nas perguntas frequentes e no texto alternativo das fotos de outras cidades.

    • n8n
    • Sitemap
    • Obsidian

  11. Aplica o desconto de IPI e o grupo de imposto produto a produto pela API, para o valor no checkout bater com o catálogo.

    Ajustei 105 produtos e conferi cada um com o cálculo de imposto do próprio Wix. 98 batem no centavo e 7 ficam um centavo abaixo.

    Também refiz o catálogo de peças como elemento personalizado, com 331 peças de duas marcas, filtros tirados do nome de cada peça e uma barra de pedido ligada ao carrinho do Wix.

    • Wix REST API
    • Custom Elements
    • JavaScript

  12. Leio os relatórios do Meta Ads em Python para decidir o que ajustar e o que deixar na fase de aprendizado.

    Depois de corrigir a segmentação, o custo por conversa de uma das lojas caiu para R$ 2,50. O melhor conjunto chegou a R$ 2,02.

Site de cliente, antes e depois

A Art 7 Epoxy reclamou que o site estava lento no celular. Entre 15 e 17 de outubro de 2026, encontrei as causas e corrigi uma por uma. Estas são as notas do PageSpeed do Google.

O que estava pesando

  • Uma cortina de transição deixava a tela em branco até a página seguinte carregar.
  • Um banner de 355 KB estava colado dentro do HTML de todas as páginas. Virou um WebP de 49 KB.
  • Chat, formulário, pixel e Google tag carregavam todos de uma vez. Agora esperam a primeira interação do visitante, ou o formulário aparecer na tela.
  • O reCAPTCHA somava 695 KB em 18 formulários que já tinham honeypot, então saiu.
  • Trinta arquivos CSS pequenos e scripts bloqueantes viraram um arquivo só, com os scripts adiados e a foto do topo pré-carregada.
